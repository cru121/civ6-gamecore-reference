# Multiplayer, lobby and Firaxis Live vocabulary of the exe

Source: strings referenced by the network functions plus a Ghidra decompile of `AddLobbyToTable` (0x266980) and `UpdateLobbyGameSettings/Map/ModMetaData` (0x294ea0, 0x2956e0, 0x295bb0). Reference page: `docs_proto/docs/exe/network.md`; data `docs_proto/data/exe_network.json` (145 entries).

- **Lua game list entry** (`Matchmaking.GetGameListEntry(id)`, used in `Lobby.lua`): `serverName`, `numPlayers`, `maxPlayers`, `Players`, `serverID` (the list index) plus 15 fields copied from lobby metadata: `MapName`, `MapSize`, `RuleSet`, `RuleSetName`, `EnabledMods`, `EnabledGameModeNames`, `Initialized`, `GameVersion`, `GameSpeed`, `GameSpeedName`, `GameStarted`, `SavedGame`, `CloudTurnPlayerName`, `VictoryName`, `VictoryPlayerName`.
- **Metadata accessor slots on the lobby interface** (Verified in the decompile, same slots in all four functions): get integer +0x148, get string +0x150, set integer +0x178, set string +0x188. So `Initialized`, `GameSpeed`, `GameStarted`, `SavedGame`, `GameLaunchReady`, `MapSize` are integers; version, names, `EnabledMods`, `RuleSet*`, map names are strings. `MapName` in the entry holds the display name (`MapDisplayName` is read, not exposed).
- Also: Epic and Steam lobby attribute names (`_LOBBY_NAME_`, `_BUCKET_`, `_LOBBY_JOIN_CODE_`, ...), cloud keys, `CCR_*` connection close reasons (11), `LMS_*` lobby member status codes (6), Firaxis Live: 20 server operations (`MatchCreate`, `MatchJoin`, `MatchStartMatch`, `EndTurnMatch`, `KickPlayerMatch`, `UpdateMatchSaveGame`, `My2KLinkAccount`, ...), 35 notification callbacks, data push topics.
- **Not recorded on purpose:** the Epic platform creation and Firaxis Live startup functions contain embedded service identifiers; they are skipped by the extractor and no value from them is in the reference. If you read those functions yourself, do not publish what you find there.
- Limits: names and types only; no message formats or network protocol. Meanings of platform keys are inferred.
