# The .modinfo vocabulary of the engine exe

Method: identifier string literals referenced by the exe's modding functions (`Modding::XmlModLoader::ParseModXml`, `ModLoaderService::ParseMod`, `AppModdingFramework` constructor, `ModdingComponentDiscoveryService`,
`ModdingSettingDiscoveryService`, the `*Criterion::Check` classes, `ModAssociationsService`, `AppLuaModdingLibrary`), cross-checked against the 42 `.modinfo` files shipped with the game (element and attribute counts only).
Reference page: `docs_proto/docs/exe/modinfo.md` (generated by `docs_proto/tools/extract_exe_modinfo.py`; notes in `docs_proto/curated/_exe_modinfo.yaml`). **Verified**: names, the functions that use them, and shipped usage counts. **Inferred**: what each component or criterion does.
- **Components / actions (22 names):** UpdateDatabase, UpdateText (LocalizedText), UpdateIcons (Icons), UpdateColors, UpdateArt (ModArt), UpdateAudio, UpdateLogitechARX / UpdateARX, ImportFiles, AddGameplayScripts (GameplayScripts), AddUserInterfaces (UserInterface),
  ReplaceUIScript, AddMap, AddWorldBuilderMap, Custom, DoNothing. Handler classes and Windows RVAs where mapped: `ModdingUpdateDatabase::ApplyComponent` 0x260150, `ModdingUpdateConfigurationDatabase` 0x260880, `ModdingUpdateTextAction::Apply` 0x261160,
  `ModdingUpdateIconsAction::Apply` 0x260cd0, `ModdingUpdateColorsAction::Apply` 0x24e760, `ModdingUpdateAudio` 0x25fe00, `ModdingUpdateARX` 0x25f970, `ModdingImportFilesAction` 0x257ac0, `ModdingGameplayScriptComponentHandler` 0x257700,
  `ModdingUserInterfaceComponentHandler` 0x261af0, `ModdingReplaceUIScriptComponentHandler` 0x25cb50, `ModdingMapSettingHandler` 0x258ba0, `ModdingWorldBuilderSettingHandler` 0x262060. There is no handler class named for UpdateArt in the symbol list.
- **Criteria (11 + 5 setting criteria):** AlwaysMet, NeverMet, ConfigurationValueMatches (Group, ConfigurationId, Value, Player; Check 0x2543d0), ConfigurationValueContains, RuleSetInUse, LeaderPlayable (Check 0x255740), MapInUse, ModInUse, GameCoreInUse,
  GameModeInUse (WorldBuilder, SinglePlayer, HotSeat, MultiPlayer; Check 0x2552c0), and for settings ModIsEnabled, ModIsInstalled.
- **Two styles:** old `InGameActions` / `FrontEndActions` + `ActionCriteria` (36 uses in the shipped files) and newer `Components` / `Settings` (6). The exe reads both.
- **Elements read by `ParseModXml`:** ActionCriteria, Block(s), Components, ConflictsWith, Criteria, Dependencies, Dependency, Exclude, Files, FrontEndActions, InGameActions, Include, Items, LocalizedText, Priority, Properties, Reference(s), Required, Requires, ReverseDependencies,
  ReverseReference(s), Settings, Value; attributes action_id, criteria, inverse, mod_id, required. Blocks, ConflictsWith, Exclude, Requires and inverse never occur in the shipped files.
- **Also in the page:** mod properties (AffectsSavedGames, EnabledByDefault, LoadOrder, ShowInBrowser, AlwaysHidden, Supports*, CompatibleVersions, Trusted, DisabledAtStartup ...), mod database fields (IsBasic, DBVersion, Created, LastUpdated),
  requirement status codes (BlockedByAssociation, MissingDependencies, OwnershipRequired, OutdatedGameVersion ...), subscription statuses and the `GetModInfo` result fields.
- Limits: `id`, `version`, `title`, `any` are read by generic code and have no string of their own; handler classes with no mapped Windows address show none.
