# City::Buildings::RemoveGreatWork

`int __thiscall RemoveGreatWork(Buildings* this, GreatWorkListIndex index)`

Clears the slot that holds a given great work in a city. Returns the slot number it was in, or -1 if this city does not hold it.

## Verified from the decompilation
- Walks the city's building entries (array at this+0xc8, count at this+0xd8, 0x20 bytes each) and each building's slots (pointer at entry+0x8, count at entry+0x18, 8 bytes each). The great work index is at slot+4.
- On the first match it writes 0xFFFFFFFF into that slot and returns the slot number within its building. It does not report which building it was in, and stops after the first match.
- It does no tourism/yield recalculation, sends no event or signal, and does not touch the game-wide great work list.

## Observed in-game (2026-09-29 to 2026-10-03, single player, Frida live channel)
- Called through the edit() accessor (command `remove`), a work leaves its slot but stays in the game-wide record list ("limbo"): the per-city getters then count no yield and no tourism for it, and Game.GetGreatWorkPlayer / HasGreatWorkBeenCreated still know it.
- Archive swap: after removing the Palace work and placing a different work into the freed Palace slot, a save/reload showed the new work with its yields in the Palace.
- Removing the whole Palace (City::Buildings::RemoveBuilding via edit()) while its slot held a work: the game did not refuse and did not crash; the building and its slots disappeared and the work went to limbo with its record intact (2026-10-03). The ghost scan found no leftover slot entries afterwards.

## Inferred (not confirmed in-game)
- Callers always obtain the city's Buildings through FAutoVariable<VariantMap,Game::Instance>::edit(city+0xca0) first. This looks like change tracking (save / multiplayer sync), so calling RemoveGreatWork on an un-edited object may skip that tracking. (Medium: mechanism read from the accessor, purpose inferred.)
- Tourism and yields appear to be computed on demand by getters (e.g. GetYieldFromGreatWorks), so nothing else needs refreshing after removal. (Medium.)

## For modders
- This is the missing 'take a great work out of a city' operation. No gameplay-side Lua method can currently do it.
- On its own it leaves the work in no city. The game pairs it with a placement call (ReceiveGreatWork) and retries if placement fails.
- See the topic note great-works-moving.md.
