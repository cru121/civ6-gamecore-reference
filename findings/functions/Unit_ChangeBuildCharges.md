# Unit::Instance::ChangeBuildCharges

`void __thiscall ChangeBuildCharges(Instance* this, int delta)`

Adds a (possibly negative) amount to a unit's remaining build charges, never going below 0.

## Verified from the decompilation
- Current charges are at unit+0x538. New value = current + delta, clamped to 0.
- Assigns through a tracked variable (CopyAssignmentDo on a FAutoVariable at unit+0x528).
- If delta != 0, sends a Reporting event (hash 0xb2176dc4) carrying the new and old values.

## Observed in-game (2026-09-29, vanilla game, single-player, Frida log-only hook)
- Address 0x3a2980 in the installed build matched the expected function prologue.
- A Builder building an improvement called it with delta = -1; the int at unit+0x538 went from 3 to 2.
- Calling it ourselves with delta = +1 (Frida, from inside the game's own call on the game thread) raised the field from 2 to 3
  (log: `charges now 3`); the user reported the builder's charges then looked correct in the UI (user-reported, not logged).
  So the address, the calling convention (this + int), the sign convention and the field at unit+0x538 are confirmed.
- Clamp confirmed: calling with delta = -100 on a unit with 2 charges left the field at 0 (log), never negative. A follow-up
  call with a positive delta restored the intended value.
- Bonus test: game spent 1 (2 -> 1), our extra call added +2 (field 3). The unit loses focus after acting; after the user
  reselected it, the UI showed the higher count (user-reported). So the displayed value follows the field, at least on reselect.
- **Exposed to Lua and tested (2026-09-29).** A local build of the Community Extension (upstream master + a ~10-line wrapper,
  `UnitManager.ChangeBuildCharges(unit, delta)`, offset 0x3a2980) plus a gameplay script that adds one charge to each Builder
  at the start of the player's turn: in a fresh single-player game Builders regained a charge each turn, as intended
  (user-reported). Needs a custom GameCore, so the mod is incompatible with other GameCore mods.
- Not yet observed: whether the UI updates instantly without reselecting (untestable in this setup because the unit
  deselects), whether the Reporting event fires for a direct call, and behavior for units other than Builders.

## Inferred (not confirmed in-game)
- The event is likely what refreshes the UI's charge display. (Medium.)

## For modders
- A small, self-contained mutator with no documented Lua equivalent. Clamping and the event come for free if this function is called instead of writing the field.
