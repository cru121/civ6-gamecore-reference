Diplomacy::Deal::Item::GreatWork::Enact

Executes a great-work trade item: takes the work out of the giver's city and gives it to the receiver.

  • Skips if the item's parent type is a particular constant (0xd384eeb7) or either player is not alive. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • Finds the giver's city that holds the work (IsInCity), calls RemoveGreatWork on it via edit(), then Player::Culture::ReceiveGreatWork for the receiver. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • If ReceiveGreatWork fails, it stores the stranded index in the deal item (this+0x90) instead of losing it, then fires a virtual notification callback. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • Giver player is at item+0x28, receiver at item+0x2c. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • The constant 0xd384eeb7 is probably a deal-type hash. (Low.) [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • This is the reference implementation of moving a great work between players; a custom mover should follow its order of operations. [inferred; evidence: static-analysis — decompilation read in Ghidra]

Diplomacy::Deal::Item::GreatWork::PostEnact

Retries placing a great work that Enact could not place.

  • If the item's stranded index (this+0x90) is not -1, calls ReceiveGreatWork for the receiver again. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • The retry likely covers deals where other items (e.g. a building or city) create room for the work first. (Medium.) [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • Shows the game tolerates a short 'work in no city' state and repairs it afterwards. [inferred; evidence: static-analysis — decompilation read in Ghidra]
