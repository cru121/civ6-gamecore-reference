Rules::Cities::Shared::Instance::RelocateBuildingGreatWorks

Re-homes a list of great works after a building replacement changes a city's slots.

  • For each work in the list: if the city's own Buildings can take it (CanAddGreatWork), it adds it there via edit() + AddGreatWork. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • Otherwise it walks the player's other cities and, for every other city where CanAddGreatWork is true, calls AddGreatWork. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • If no city can take it, nothing happens: no notification, no record, no fallback. The work simply ends up in no slot. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • The loop over other cities has no break/return after a successful add. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • A work that fits nowhere is silently dropped from all slots (it probably still exists in the game-wide great work list). (Medium.) [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • Because the loop does not stop after the first successful add, the same work could be added to more than one other city if CanAddGreatWork only checks the target city and not other cities. Possible duplication bug. (Low: depends on what CanAddGreatWork checks, not yet read.) [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • One concrete way works "get lost": a building replacement with no spare slots elsewhere. The work is neither archived nor reported. [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • Relevant to any 'great works archive' idea: this is a point where a work could be saved instead of dropped. [inferred; evidence: static-analysis — decompilation read in Ghidra]
