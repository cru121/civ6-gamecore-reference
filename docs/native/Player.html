Player::Culture::ReceiveGreatWork

Gives a great work to a player by placing it in the first of their cities that can hold it. Returns false if no city has room.

  • Iterates the player's cities (list from player+0x6d0 -> +0xd0, next node at +0x10). For each: gets the city's Buildings via edit(city+0xca0), calls CanAddGreatWork, and stops at the first city that says yes. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • Then calls Buildings::AddGreatWork on that city and returns true. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • none [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • The placement half of a trade. A false return leaves the work unplaced; the deal code stores it and retries in PostEnact. [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • Creating a work (FindOrAddGreatWork + SetGreatWorkPlayer) and calling ReceiveGreatWork for the player placed it in the free Palace slot ("PLACED in a slot"); the capital then showed culture +2 and tourism +2 for a Writing work. Repeated on 2026-10-03 with the live channel. [verified; evidence: runtime — Observed in-game (2026-09-29 to 2026-10-03, single player, Frida live channel)]

Player::Diplomacy::SetHasOpenBordersFrom

Grants (+1) or revokes (-1) open borders from another player. It is a counter, not a flag.

  • Per-player counter at Diplomacy+0x490 + player4: new = old +/- 1, clamped at 0. Stored through edit(). [verified; evidence: static-analysis — decompilation read in Ghidra]*
  • When the counter reaches 0: records the current game turn (game+0xc0) in the per-player array m_iOpenBordersEndedTurn (tracked-variable wrapper at Diplomacy+0x590, so the array starts at +0x5a0; name from Linux debug info, see topics/linux-debug-symbols.md), indexed by player4, calls ExpelFromTerritory, and dispatches an 'ended' signal. [verified; evidence: static-analysis — decompilation read in Ghidra]*
  • On the 0 -> 1 transition it dispatches a 'started' signal. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • Multiple sources (deals, agreements) each add 1, so revoking one does not end open borders while another remains. (Medium.) [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • Granting twice needs two revokes to end. A wrapper should expose the counter semantics clearly, or offer a 'set to exactly N' variant. [inferred; evidence: static-analysis — decompilation read in Ghidra]

Player::Religion::CreateRelic

Creates a relic near a plot and places it in the nearest relic slot.

  • Calls GetNearestRelicSlot for the plot (returns a city plus building type and slot), then Game::Culture::AddRelic. If that returns a valid great work, it looks up the slot's work and sends a Reporting event (hash 0x1a71e9f0). [verified; evidence: static-analysis — decompilation read in Ghidra]
  • If GetNearestRelicSlot finds no free relic slot, the function does nothing at all: no relic is chosen, no record is created, no event is sent. (The relic is chosen inside AddRelic, which is only called when a slot exists.) This is the "relic lost when slots are full" behavior. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • Direct callers (13): the combat resolvers (ResolveMeleeUnitVsUnitCombat and siblings, AttackInto), Map::Player::Visibility::Manager::ViewPlotContents, Unit::Commands::SpreadDissent::Start, and GameEffects::Effects::GrantRelic::Apply (a modifier effect). All relic sources funnel through this one function. Which caller is the goody hut, apostle death or city-state perk is inferred from the names, not verified. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • Any notification or era score a player sees when the slots are full is produced by the caller or another system, not by this function or AddRelic (which only announce on success). (Medium; not traced.) [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • Relics use the same slot machinery as other great works (AddRelic reaches AddGreatWorkToSlot). (Medium.) [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • A bridge between religion and the great work slot system; worth reading alongside the great works topic. [inferred; evidence: static-analysis — decompilation read in Ghidra]
  • With the stock DLL and every relic slot full, calling CreateRelic left the game-wide great work record count unchanged: the relic is never created (it stays in the pool), it is not created and thrown away. [verified; evidence: runtime — Observed in-game (2026-09-30, single player)]
  • A hook that, for a human player with no free relic slot, calls AddRelic with an out-of-range slot instead creates the record and archives the relic: confirmed with the hut xN test command (the Palace holds one relic slot; relics were archived only once it was full). [verified; evidence: runtime — Observed in-game (2026-09-30, single player)]

Player::Religion::GetNearestRelicSlot

Finds the player's city with a free relic slot that is nearest to a plot. Returns null when the player has no free relic slot anywhere.

  • Looks up the great work object type GREATWORKOBJECT_RELIC and reads its list of building types that can hold relics (list at definition+0x40..+0x48). [verified; evidence: static-analysis — decompilation read in Ghidra]
  • For each of the player's cities (player+0x6d0 city list) that has such a building and a free slot (Buildings::GetFreeSlot != -1), it measures the plot distance to plot and keeps the nearest. If plot is not valid it returns the first city found. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • The two output parameters (building type, slot index) are written only when a city was found. [verified; evidence: static-analysis — decompilation read in Ghidra]
  • Verified in game: when plot is invalid (the game's own "no plot" value), it returns the first city with room and does not write the output building/slot [verified; evidence: static-analysis — decompilation read in Ghidra]
  • Verified in game: the Palace counts as a relic slot holder at the start of a game (relic-holding building types: 1, 12, 13, 62, 82, 87, 95, 109). [verified; evidence: static-analysis — decompilation read in Ghidra]
  • "No relic slot" means either no relic-holding building exists yet or all are full. Both return null here. [inferred; evidence: static-analysis — decompilation read in Ghidra]
