Engine executable. Settings and tools of the game program (CivilizationVI.exe), usable without a mod. Mostly undocumented debug and configuration functionality; descriptions come from analysis of the executable and have not all been tried in the running game.

The .modinfo vocabulary

Everything the engine executable understands in a mod: the elements and attributes of a .modinfo file, the component (action) types, the criteria, the properties, and the codes returned to the mod browser. The names are the string literals of the code that parses and applies mods (Modding::XmlModLoader, ModLoaderService, the Modding* handlers and criteria classes); they are cross-checked against the 42 .modinfo files that ship with the game, so each row shows whether the game itself uses the name.

What is verified. The name exists in the exe, and the function that uses it (or the count in the shipped files). What is inferred. The explanation of what a component or criterion does: it comes from the handler class name, the files that use it and the strings inside its handler, and none of it was tried in the running game.

There are two styles in use. Old-style files list components under InGameActions / FrontEndActions with a separate ActionCriteria block (used in 36 places by the shipped files); newer files use Components and Settings (6 places). The exe reads both.

Names that the exe reads but no shipped file uses are options the game supports without showing an example (for example AffectsSavedGames appears once, Blocks, ConflictsWith and Exclude never).
