Engine executable. Settings and tools of the game program (CivilizationVI.exe), usable without a mod. Mostly undocumented debug and configuration functionality; descriptions come from analysis of the executable and have not all been tried in the running game.

Developer tools and crash reports

The exe contains the remote tools Firaxis used to develop the game and the code that writes crash reports. They are off in a normal game; the tuner needs the EnableTuner option of the Debug section. This page lists the command words the tuner listeners accept, the asset hot-load commands, the automation hooks, the elements of the bug submission header and the exception names the crash handler prints. Verified: the command words (read from the exe), the dispatch order, handler addresses and strings. Inferred: what each command does (from the handler names and reply strings). Nothing here was tried against a running tuner.

FireTuner (AppTuner2) commands

The listener Tuner::AppTuner2::Listener::ProcessInput (0x4f5bf0) receives text messages with an 8-byte header followed by COMMAND:arguments. The application commands are compared first. Any other message is read as <state index>:COMMAND:arguments: the number picks one of the registered Lua states (the main state and threads, AddLuaState) and the command is one of the Lua state commands. HOTLOAD takes a kind as its first argument (ARTDEF, UI, anything else is a blueprint reload).

Asset hot loading (AssetCloud)

A second listener, AssetCloud::Listener::ProcessInput (0x4ef4f0), accepts CLOSE and HOTLOAD and logs to AssetCloudTuner.log. The hot loader keeps a queue of ARTDEF: and DEPENDENCY: entries and a temporary workspace folder that it removes when it closes.

Command Meaning
CLOSE close the asset cloud connection (log: "Received close request.")
HOTLOAD hot load a file (log: "Received Hotload request: '%s'." then "HotLoad complete."); queue entries are ARTDEF: and DEPENDENCY: (log: "Adding ArtDef/BLP '%s' to the hot load queue")

Automation hooks

The automation manager (switches -autoscript, -autoparams, -autojson on the command line; Lua table Automation) raises these events and uses these tags in output file names:

Name Meaning
AutomationAppInitComplete raised when the app finished initialising (Automation::Manager::OnAppInitComplete)
AutomationMainMenuStarted raised when the main menu started
AutomationPostGameInitialization raised after game initialisation (Automation::Manager::PostGameInitialization)
$(Automation) file name tag replaced by the automation folder in output file names
$(ID) file name tag replaced by the run id
Automation_%04d_%02d_%02d__%02d_%02d_%02d default automation output name pattern (date and time)

Bug submission header

AppHost::BugSubmissionPackager::GenerateHeaderInSubmissionFolder (0x705e70) writes a header document into the submission folder (a folder with the log, the dump and attachments). Elements in the order they are written (the grouping under a parent is inferred from the order of repeated names):

# Element Notes
1 GUID
2 Application
3 SubmissionType
4 Host
5 Time formatted %04d-%02d-%02d %02d:%02d:%02d
6 File
7 Line
8 Message
9 Callstack
10 Catalog
11 Log child File, MD5
12 Dump child File, MD5
13 Attachments child File, MD5
14 Exception children Message, StackTrace, ModuleInfo
15 ModuleInfo attributes file, baseAddr, size, guid1, guid2, guid3, guid4, age, pdbPath
16 Version children Major, Minor, Rev, Build, Changelist
17 Session children Hash, Time

Collection is switched by the EnableBugCollection option and the -NoAssertCollection switch (see the options and command line pages).
