Home › Engine executable › Telemetry configuration

Engine executable. Settings and tools of the game program (CivilizationVI.exe), usable without a mod. Mostly undocumented debug and configuration functionality; descriptions come from analysis of the executable and have not all been tried in the running game.

Telemetry configuration

The engine executable ships with a default telemetry configuration: two XML documents embedded in the code that say which events the game can report and which usage counters it keeps. This page lists them as written. It describes the built-in configuration only: the game can also download a configuration from the Firaxis Live service (App/FiraxisLive/OnlineTelemetryConfiguration.xml, fetched through a service discovery step), which can replace it, so what an individual game reports today may differ. This analysis did not look for a way to switch reporting off and makes no claim about what is actually sent on a given machine.

Verified: the event names, flags and counters are literals in the exe. Not determined: what the SendFlags values 4 and 8 mean, and the data fields of each event.

What the code does with it

From the messages in the telemetry code: events are put in queues with a priority, can be rejected by sampling or by priority, are flushed periodically (and on shutdown) to a /telemetry/v2 service endpoint with retries, and the configuration entries are fetched with retries as well. The game logs a line such as Sending Telemetry: OrgEvent=... Type=... SendFlags=... (function GameCore::App::Telemetry::Listener::OnTelemetryTag). There is one related entry in the option files: [Misc] TelemetryUploadNecessary (see the option files).

Events of the default ruleset

The default ruleset (flagged IsBlacklist in the XML) lists 54 events, 39 of them enabled. Two derived rulesets, Elite Player Ruleset and New Player Ruleset, inherit from it and change the update interval of a few events. TurnInterval means the event is repeated every that many turns.

Counter tables

Seven tables of counters are kept during a game and reported as events (ScreenBreakdown, LensBreakdown, EnvBreakdown, PrjFrequency, PowerStats, WorldCongress, GameLevel). Kind says what is counted (a UI context, a lens, a terrain state change, a building or district type, or a free-form value), Type how (a count, seconds, or a value that is set).
