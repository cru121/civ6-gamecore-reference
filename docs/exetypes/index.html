Engine executable. Settings and tools of the game program (CivilizationVI.exe), usable without a mod. Mostly undocumented debug and configuration functionality; descriptions come from analysis of the executable and have not all been tried in the running game.

Reflected data types

The exe describes many of its own data structures to a reflection system (GetTypeInfo and GetEnumInfo functions): every field gets a name, a type and a byte offset, every enum member a name and a value. They are the layouts of the serialized formats the game loads: the artdef object model, the blueprint (.blp) packages (775 .blp files ship with the game), leader, landmark and terrain packages, model and effect data. This section lists 264 struct layouts (1104 fields) and 14 enums. Verified: field names, offsets and enum values are constants in the code; Inferred: what a structure is used for (from its name). Field types are the type functions the code calls; where the function had no name in the function map its own type-name string is used, and 51 fields remain "(not resolved)".

Cross-check. The artdef XML files name their elements after these fields: 29 of the 32 distinct m_... element names in the shipped .artdef files (base game and DLC) are field names of the reflected types (not matched: m_b, m_g, m_r).

These are in-memory layouts of the 64-bit Windows exe (offsets include pointers of 8 bytes and the alignment the compiler chose); they are not the on-disk byte layouts of the files, which can differ.
