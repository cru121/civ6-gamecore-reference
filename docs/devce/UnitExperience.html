CanEarnPromotion

Arguments: ePromotion — Promotion type to test; bIgnoreRandomPromotionCheck — If true skips the proposed-promotion (random choice) check

Input checks: Checks promotion index validity and ownership; unit type pointer used without null check.

Multiplayer: read-only; evaluates unit state. Risk: low (pure check). Confidence of the reading: medium.

ChangeGeneralExperienceModifier

Arguments: iDelta — change in percent

Writes - fixed-point modifier at this+0x28

Side effects - none

Input checks: none needed

Preconditions - valid Experience object

Multiplayer: safe-deterministic. Risk: low (simple arithmetic; uses floorf but deterministic). Confidence of the reading: high.

Verified from the code - multiplies iDelta by a float constant (likely 0.01) - splits into integer and fractional (x256) parts and adds to +0x28 as (int<<8)/frac

Inferred - constant is 1/100 so iDelta is a percent - stored as 8-bit fixed point

Open questions - float constants not read directly (symbol names only)

CheckPromoteNotification

Writes - Experience flag at +9 cleared

Side effects - Creates or updates the promote-unit notification for the owner

Input checks: Only acts for human players; returns if notification creation fails.

Multiplayer: may-desync; notifications and unit flag, human only. Risk: low (notification only). Confidence of the reading: medium.

GetExperienceModifier

Arguments: bIsUnitAttacking — If true, adds the attacking experience component (inferred)

Input checks: None.

Multiplayer: read-only; computes from state. Risk: low (pure getter). Confidence of the reading: low.

GrantPromotion

Arguments: ePromotion — promotion type; bIgnoreRandomPromotionCheck — skip the random-promotion restriction in CanEarnPromotion (inferred)

Writes - owner player's Units promotion-selected state via SetPromotionSelected - unit promotion list via SetPromotion

Side effects - Player::Units::SetPromotionSelected(unit type, promotion, false) - Experience::SetPromotion

Input checks: silently does nothing when CanEarnPromotion returns false; owner index not bounds checked

Preconditions - unit belongs to a valid player - gameplay thread

Multiplayer: safe-deterministic. Risk: low (guarded by CanEarnPromotion). Confidence of the reading: high.

Verified from the code - calls CanEarnPromotion with both args first - on success updates owner's Units via SetPromotionSelected then SetPromotion

Inferred - bool name from Linux debug info implies it bypasses random promotion gating

Open questions - what exactly CanEarnPromotion checks

SetLevel

Arguments: iLevel — new level

Writes - level at this+0x10

Side effects - sends Reporting::Event 0xa038d885 with unit id and new level (always, even if unchanged)

Input checks: No validation of level range or unchanged value.

Preconditions - gameplay state

Multiplayer: safe-deterministic. Risk: medium (Unvalidated level could break promotion logic). Confidence of the reading: high.

Verified from the code - writes level unconditionally - always sends event - does not touch XP or promotions

Inferred - promotion availability may depend on level vs promotions taken

Open questions - whether other code expects level to match XP

SetLevelAndExperience

Arguments: iLevel — New experience level; iExperience — Experience points passed to ChangeExperience

Writes - Experience level at +0x10 - Experience fields at +8,+0xa,+0xc reset - Experience points via ChangeExperience

Side effects - Whatever ChangeExperience triggers (possible promotion notification)

Input checks: None; level not range checked.

Multiplayer: may-desync; writes synchronised unit experience. Risk: medium (unvalidated level and xp). Confidence of the reading: medium.
