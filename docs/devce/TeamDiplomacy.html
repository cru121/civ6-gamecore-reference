ChangeYieldPerDelegation

Writes - int array element indexed by the yield definition's index in the array at this+0x10d0; if the index is out of range, a fallback/default field at offset 0x18 of the array object is written instead

Side effects - none

Input checks: Yield -1 returns silently. Out-of-range definition index falls back to writing the default slot rather than crashing. A null Find result would crash (not checked).

Preconditions - valid yield type

Multiplayer: may-desync: player state mutation; must run identically on all clients. Risk: low (bounds-checked assignment; semantic mismatch with name). Confidence of the reading: medium.

Verified from the code - parameter is assigned, not accumulated - uses yield definitions Find to get an index at +0x14 - index checked against array size

Inferred - Ghidra labels the Find result as Government due to template folding; it is really a Yield definition - the +0x18 field is a default/overflow value

SetHasOpenBordersFrom

Arguments: ePlayer — other player granting the open borders; bNewValue — true adds one, false removes one

Writes - open-borders counter array at this+0x480, indexed by ePlayer (clamped at 0) - turn-of-expiry array at this+0x590, indexed by ePlayer (current game turn from game+0xc0)

Side effects - when count reaches 0: calls ExpelFromTerritory(ePlayer) and dispatches a signal (game signal at +0xde0) with unit/player instance - when count becomes 1 by adding: dispatches a different signal (game signal +0xdc8) - sends Reporting::Event 0x52e2805c with owner id and bNewValue

Input checks: ePlayer is used as an unchecked array index; invalid id is a crash/corruption risk. Counter never goes below 0.

Preconditions - valid ePlayer index - gameplay state

Multiplayer: may-desync: mutates replicated diplomacy state and expels units; must execute identically everywhere. Risk: high (Unchecked player index and expels units). Confidence of the reading: medium.

Verified from the code - counter is incremented/decremented by 1 and floored at 0 - edit() called on the variant map before each write - event is always sent - no bounds check on ePlayer

Inferred - offsets +0x480/+0x590 look like per-player int arrays - the signal arguments are the other player instance and the owner instance

Open questions - what the two signals are named - what the +0x590 array is used for exactly (assumed last-turn-ended)
