ChangeProductionModifier

Arguments: iDelta — percent change

Writes - per-item modifier int array at this+0x2f0 (indexed by type)

Side effects - none

Input checks: returns silently for type -1; no bounds check on index otherwise

Preconditions - valid index into the modifier array

Multiplayer: safe-deterministic. Risk: medium (unchecked array index). Confidence of the reading: medium.

Verified from the code - Linux debug info lists three overloads (building, district, project) sharing this address - scales delta by a constant and stores fixed point added to array element at +0x2f0 + 4*index

Inferred - same code used for all three overloads due to identical code folding - constant is probably 0.01

Open questions - whether a given overload uses a separate array in the real build (folded here)

SetDistrictPercentComplete

Arguments: eDistrict — district type; iPercent — percent of cost completed

Writes - district progress array at this+0x248 (value = cost*percent/100 in 24.8 fixed point)

Side effects - none

Input checks: silently ignores district ids outside definitions or with null definition; percent not clamped

Preconditions - owning city set at this+0x1e8

Multiplayer: safe-deterministic. Risk: low (guarded; only sets progress). Confidence of the reading: high.

Verified from the code - range and null check on definition - uses existing district's stored cost if the district exists else Player::Districts::GetCost - stores ((cost*percent)/100)<<8

Inferred - array at +0x248 is district production progress

Open questions - whether percent above 100 is handled elsewhere
