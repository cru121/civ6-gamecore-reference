AddOutgoingVisibilityBlocker

Arguments: eFromPlayer — player whose outgoing visibility is blocked; eToPlayer — player who stops receiving the visibility

Writes - Visibility counts of eToPlayer per plot (decrement) - blocker set on eFromPlayer instance

Side effects - PropagateVisibilityChanges for local observer

Input checks: Both players must be <0x40 and mapped, otherwise nothing happens; counts clamped at 0.

Multiplayer: may-desync, changes player visibility. Risk: high (Alters fog state; return value looks unreliable). Confidence of the reading: medium.

AddPlotYield

Arguments: iPlotIndex — plot index; eYield — yield type; iAmount — amount to add; event only for >0

Writes - per-plot yield entry in variant map at this+0xb0 (creates entry if absent, adds amount to the yield slot)

Side effects - Reporting::Event::Send hash 0x45b517d6 with plot, city and localized text, only when amount>0 and plot visible

Input checks: Invalid plot or amount<1 skips the event but still performs the stored add (amount added even if negative); out-of-range plot index goes to a scratch entry; out-of-range yield adds to a fallback field.

Preconditions - game thread - valid plot index recommended

Multiplayer: may-desync: event depends on local observer visibility but state change is deterministic. Risk: medium (stored yield change plus local-only UI event). Confidence of the reading: medium.

Verified from the code - uses virtual map GetPlot at vtable+0x60 - message only when amount >= 1 and local visibility value > 0 - bounds checks for index and yield; fallback writes elsewhere - switch on yield 0-5 selects text, all cases fall to same code in decompile

Inferred - the +0xb0 map is plot index to yield list - the sent event is the plot yield popup

Open questions - what the fallback fields at +0x18/+0x30 of the scratch entry represent

Preconditions - gameplay state - map with volcano features - game thread

Multiplayer: may-desync: uses the shared random generator and emits UI notifications; must run identically on all clients. Risk: high (Consumes random state and sends notifications; call order matters for sync.). Confidence of the reading: medium.
