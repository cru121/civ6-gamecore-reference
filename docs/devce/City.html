AddCityHappinessModifier

Arguments: eHappiness — happiness state the modifier applies to; eYield — yield affected; eGreatPersonClass — great person class affected; iYieldChange — yield change; must be >0 unless iGreatPersonChange >0; iGreatPersonChange — great person point change

Writes - 20-byte modifier record appended to the vector held in the city's auto variable at this+0x710

Side effects - may reallocate the vector

Input checks: Silently does nothing unless iYieldChange > 0 or iGreatPersonChange > 0. Enum values are stored unchecked and not deduplicated.

Preconditions - game thread - gameplay state

Multiplayer: safe-deterministic. Risk: low (Append to a synchronised auto variable; no validation of enums.). Confidence of the reading: high.

Verified from the code - Returns without effect when both change values are not positive - Writes through FAutoVariable::edit at this+0x710 and appends five 4-byte fields - Record type is typed as BeliefYield in symbols but the field is City happiness modifiers

Inferred - Record semantic is 'when city is in this happiness state, add yield/GP'

Open questions - How RemoveCityHappinessModifier matches records (see that function)
