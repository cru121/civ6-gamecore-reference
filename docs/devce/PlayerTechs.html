GrantRandomBoostGoodyHut

Arguments: iNumFreeBoosts — how many boosts to grant; eSource — source of the boost, passed to TriggerBoost

Writes - triggers tech boosts through Techs::TriggerBoost - consumes random numbers

Side effects - calls Techs::TriggerBoost per selected tech - advances game RNG (label: Choosing random tech boost to grant based on era) - heap-allocates candidate list on overflow

Input checks: Does nothing if count <= 0 or no candidates; tech ids of -1 or out of range skip the already-boosted checks.

Preconditions - valid player - game thread

Multiplayer: safe-deterministic. Risk: low (normal gameplay path using game RNG). Confidence of the reading: medium.

Verified from the code - structure mirrors the Culture version: find lowest-era unowned tech, collect its era's available boosts, pick randomly without repeats - uses GetRandNum with the label 'Choosing random tech boost to grant based on era' - calls TriggerBoost for chosen techs not already boosted

Inferred - decompiler mislabels Government/Culture types; actual types are technologies

Open questions - exact era selection due to decompiler type confusion

GrantRandomBoostsByEra

Arguments: iNumFreeBoosts — number of boosts to grant; eStartEra — first era of range; eEndEra — last era of range

Writes - tech boost state via TriggerBoost(tech, 3)

Side effects - TriggerBoost per chosen tech with source 3 - consumes game RNG draws (named 'Choosing random tech boost...')

Input checks: Silent no-op if either era is not found; stops when no candidates remain.

Preconditions - game thread - valid eras

Multiplayer: safe-deterministic: uses the synced game RNG with a log string. Risk: medium (triggers boosts, RNG consumption). Confidence of the reading: medium.

Verified from the code - filters by era range, HasBoost, HasCivic, not HasTech, not already triggered - picks via Game::Instance::GetRandNum and removes chosen from list - calls TriggerBoost with 3

Inferred - HasCivic on the tech id is likely a mislabeled check - candidate weights are all 1

Open questions - meaning of TriggerBoost source value 3 - oddity of HasCivic check on a tech id

SetAllTechsByPreviousEra

Arguments: eEraType — era; techs from earlier eras are granted

Writes - tech-researched byte array at this+0x128

Side effects - Units::RecomputeAllCosts and Districts::RecomputeAllCosts for each tech granted - signal (Unit*,uint) at game signal +0x12f0 with player and tech id

Input checks: Era pointer used unchecked if index out of range (null deref risk); does nothing when era index <=1.

Preconditions - game thread - valid era

Multiplayer: may-desync: bulk grant. Risk: medium (bulk tech grant, expensive recompute per tech). Confidence of the reading: medium.

Verified from the code - only techs with era value below target - recomputes unit and district costs for each - dispatches per-tech signal

Inferred - does not grant eurekas or tech side effects beyond the signal

Open questions - whether already known techs are re-signalled (no check seen)

SetNumFreeTechBoostOnNewEra

Arguments: numBoosts — amount added to the stored count (despite the Set name it is additive); applyImmediately — also grant random boosts now for the current era

Writes - int auto-variable at this+0x1a0 (stored count at this+0x1b0 plus numBoosts)

Side effects - when applyImmediately, current era valid and numBoosts > 0: calls GrantRandomBoostsByEra, which grants random tech boosts (uses random numbers)

Input checks: Immediate grant is skipped if the era is -1 or numBoosts is not positive. The stored count is updated regardless.

Preconditions - gameplay Lua state only - owner player must be set

Multiplayer: may-desync: random boost selection must use the synchronized game RNG. Risk: medium (additive despite Set name, plus random grant side effect). Confidence of the reading: medium.

Verified from the code - stored value = old + numBoosts - calls GrantRandomBoostsByEra only if applyImmediately, era != -1 and numBoosts > 0

Inferred - GrantRandomBoostsByEra takes the era twice, probably a from/to range - negative numBoosts reduces stored count

Open questions - whether the era-change handler consumes the stored count
