ChangeGoldDiplomaticDeal

Arguments: dealId — diplomatic deal id; dealItemId — item id within the deal; addDeal — true to append the pair, false to remove all matching pairs

Writes - vector of (uint,uint) pairs in the variant map at this+0x1b0 (append or erase) - gold yield cached values (via CalculateGoldYieldExcludingTrade)

Side effects - recomputes the gold yield excluding trade, which may change displayed income

Input checks: No check for duplicates on add, so the same pair can be added repeatedly. On remove, matching pairs are erased and a missing pair is a no-op. No id validation.

Preconditions - gameplay Lua state only - must run on the game thread

Multiplayer: may-desync: replicated list change plus yield recalculation. Risk: medium (list edit with duplicates allowed; affects gold income). Confidence of the reading: medium.

Verified from the code - add path appends a pair of the two ids to the vector at this+0x1b0 - remove path compacts out all pairs equal to both ids and erases the tail - always calls CalculateGoldYieldExcludingTrade at the end

Inferred - pairs identify gold deal items counted in income - the vector append template name is mis-resolved but behaves as a push_back

Open questions - how the list is consumed when computing gold

ChangeGoldInterestPercent

Arguments: xPercent — delta to the interest percent (raw/256)

Writes - gold interest percent auto-variable at this+0xe0 (value mirrored at this+0xf0) set to old+delta, then to 0 if negative

Side effects - assigns through an FAutoVariable move-assignment; edit() used for the clamp

Input checks: No bounds on delta; negative result is clamped to 0. xPercent pointer not checked.

Preconditions - gameplay Lua state - valid Treasury object - game thread

Multiplayer: may-desync: mutates synced game state; only safe when run identically on all clients. Risk: low (simple clamped additive change). Confidence of the reading: medium.

Verified from the code - new value = value at 0xf0 plus delta, assigned to variable at 0xe0 - if value at 0xf0 is negative afterwards, edit() is called and zero is written

Inferred - the variable is the gold interest percent, from the name; the Ghidra ControlPriority template name is likely code folding of the same assignment

Open questions - whether 0xf0 is the live value or a cached copy of 0xe0
