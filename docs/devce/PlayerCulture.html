AddTourismAtPlot

Arguments: iPlotIndex — plot index; iTourism — base tourism before modifier

Writes - tourism location vector at this+0x648 (existing entry amount increased or new entry appended)

Input checks: No plot validation; modifier clamped at -100.

Preconditions - game thread

Multiplayer: may-desync: synced vector. Risk: low (append/add only). Confidence of the reading: medium.

Verified from the code - amount = (max(mod,-100)+100)*tourism/100 using integer division - finds entry by plot index with find_if - adds or appends

Inferred - modifier pointer chain is the player's tourism modifier

Open questions - what source is at +0x6f0 -> +0x508

ChangeTourismOn

Arguments: ePlayer — player the tourism is directed at; xValue — amount to add (raw/256)

Writes - tourism-on-player array entry at this+0x480 (index ePlayer)

Side effects - none beyond marking the game variable edited

Input checks: Silently ignores ePlayer >= 0x16 (22); the check is unsigned so negatives are ignored too.

Preconditions - valid player id < 22 - game thread

Multiplayer: may-desync: edits synchronized state directly. Risk: low (bounds-checked simple add). Confidence of the reading: high.

Verified from the code - bound check param < 0x16 - reads old value, calls edit, writes old+delta - delta is read through a pointer (FixedPoint passed by reference)

Inferred - value is FixedPoint raw int; no clamping

Open questions - why the limit is 22 rather than 64 (likely only majors)

GrantRandomBoostGoodyHut

Arguments: iNumFreeBoosts — how many boosts to grant; eSource — source of the boost, passed to TriggerBoost

Writes - triggers civic boosts through TriggerBoost - consumes random numbers

Side effects - calls Culture::TriggerBoost for each chosen civic - advances the game random number generator (label: Choosing random civic boost to grant based on era) - heap-allocates a candidate list when it overflows inline storage

Input checks: Does nothing if count <= 0 or no candidate boosts. Civic ids of -1 or out of range skip the already-boosted checks.

Preconditions - valid player - game thread

Multiplayer: safe-deterministic. Risk: low (uses the game RNG with a fixed label, normal gameplay path). Confidence of the reading: medium.

Verified from the code - picks a lowest-era civic not yet owned/boosted then collects its era's boosts that exist and whose civic is not already owned - draws with Game::Instance::GetRandNum using the label 'Choosing random civic boost to grant based on era' - removes each chosen entry from the candidate list so no repeats - calls TriggerBoost for each selection not already boosted

Inferred - target era is the lowest era among unowned civics - decompiled types are misleading (government/tech names reused for civics)

Open questions - exact era-selection logic is partly garbled by decompiler type confusion - whether the HasBoost check refers to the era's boost objects

GrantRandomBoostsByEra

Arguments: iNumFreeBoosts — how many boosts to grant; eStartEra — lower era bound (inclusive); eEndEra — upper era bound (inclusive)

Writes - calls TriggerBoost on this player (source code 2) for each chosen civic

Side effects - draws random numbers from the game random stream (labelled with a log string including the player id) - triggers civic boosts

Input checks: if either era is not found in definitions the candidate list stays empty and nothing is granted; loop stops when candidates run out

Preconditions - valid owning player - game thread; deterministic RNG state

Multiplayer: safe-deterministic. Risk: medium (consumes game RNG and triggers boosts; fine if run on all clients). Confidence of the reading: medium.

Verified from the code - builds a weighted candidate list of civics with weight 1 - random index chosen via Game::Instance::GetRandNum with a log text including the player id - chosen entry removed from list then TriggerBoost(civic, 2) called - stops at iNumFreeBoosts or when list is empty

Inferred - candidate items are civics (names TechTypes in decompile are reused types) - era filter compares an era index field at +0x1c

Open questions - meaning of TriggerBoost source value 2 - decompile mixes tech/civic type names so list element type is unsure
