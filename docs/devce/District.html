ChangeExtraRegionalYield

Arguments: eYield — yield type; iDelta — amount to add

Writes - per-yield int array in auto variable at this+0x2a8 (or a fallback int at container+0x18)

Input checks: Silent no-op for yield outside 0..NUM_YIELD_TYPES-1.

Preconditions - game thread

Multiplayer: safe-deterministic. Risk: low (Bounds checked counter change.). Confidence of the reading: medium.

Verified from the code - Range-checks the yield - Adds iDelta to element eYield of the array when within container length - Otherwise adds to a field at container+0x18

Inferred - Regional yield means yield shared to other cities in the region

Open questions - Purpose of fallback field

ChangeGreatPersonPointChange

Arguments: eClass — great person class index; xChange — amount to add (raw/256)

Writes - per-class FixedPoint array in auto-variable at this+0x1e8 (great person point change)

Side effects - marks the auto-variable as edited (network/replication tracked state)

Input checks: Checks index is non-negative and below array size; otherwise silently ignored.

Preconditions - valid district - class index in range

Multiplayer: safe-deterministic. Risk: low (bounds-checked add through tracked edit()). Confidence of the reading: medium.

Verified from the code - bounds check on class index - add via FAutoVariable edit

Inferred - the array is the per-turn rate, not accumulated total (from name) - size check uses the array at +0x1f8 while edit is on +0x1e8, likely the same data

Open questions - whether cached player GP rates are refreshed elsewhere

ChangeRemainingAttackCount

Arguments: iDelta — change in remaining attacks

Writes - remaining attack count at this+0x360 (auto-variable wrapper at +0x350)

Side effects - none

Input checks: negative result clamped to 0; no upper cap

Preconditions - valid district instance

Multiplayer: safe-deterministic. Risk: low (clamped counter). Confidence of the reading: high.

Verified from the code - sets value to current + iDelta then re-assigns 0 if negative

Inferred - field is the district's attack counter reset each turn

Open questions - where the maximum is enforced

SetComplete

Arguments: bState — new completion state; bOriginalCompletion — passed through to the city-signal (first-time completion flag) (inferred)

Writes - district complete flag (auto variable at this+0x3e8) - player add-on district founding counters (decremented by 1 per paid entry) - creates units in the city or awards free great person

Side effects - dispatches a player signal (PlayerTypes, BeliefTypes) on the owner - dispatches a game signal (City*, bool) - City::Manager::CreateUnit for non-great-person add-on units, with alternate location search - Game::GreatPeople::AwardFreePersonByClass for great person class units - may move units to find a free placement

Input checks: Flag is always written. Everything else only when bState is true, a game exists and the district has a city. District index from this+0xf0 is bounds checked against definitions (null definition otherwise leads to a null deref).

Preconditions - gameplay state - district attached to a city - game thread

Multiplayer: may-desync: creates units and awards great people; deterministic if run on all clients, but dangerous from Lua on one side only. Risk: high (Spawns units/great people and fires signals; invalid district index would read a null definition.). Confidence of the reading: medium.

Verified from the code - Writes the bool into the auto variable at this+0x3e8 first - If true and a city exists: dispatches two signals - Looks up the owner's add-on district founding map keyed by a hash from the district definition and iterates it - For each entry with nonzero count: great person class unit awards a free person, otherwise creates a unit in the city after trying to find an alternate plot - Decrements the founding counter by 1 afterwards

Inferred - Second signal's bool is the 'original completion' flag - This implements 'free unit on first district built' style abilities

Open questions - Meaning of local_res10 map key (district hash at definition+0x1c) - Exact signal names

SetSiegeStatus

Arguments: bIsUnderSiege — new siege flag

Writes - bool at this+0x440 (auto-variable at this+0x430)

Side effects - sends Reporting::Event 0xfbada2c8 with district ids and the new flag

Input checks: No-op if unchanged. If the plot has no owner, the district is treated as null and its fields are read through a null pointer (crash risk). Result of Districts::Find is not null-checked.

Preconditions - district on an owned plot - gameplay state

Multiplayer: safe-deterministic. Risk: medium (Possible null dereference when plot is unowned or district not found). Confidence of the reading: medium.

Verified from the code - early-out on equal value - looks up owner via plot and Districts::Find - reads from the found pointer without a null check

Inferred - the event identifies the district by its player-list instance

Open questions - whether a null pointer is ever reached in practice
